# 두리(Dool2) 개인정보처리방침 주장과 공개 소스 대조

작성일: 2026년 11월 24일

## 1. 요약

- 두리는 소스가 공개된(Apache-2.0) PC용 AI 비서다. 개인정보처리방침과 사이트가 내세우는 주장을 0.4.3 릴리스 소스와 대조했다.
- "대화·기록·페이지 내용은 회사 서버로 보내지 않는다"는 주장은 소스와 일치한다. 회사 서버로 가는 통신은 이용 통계, 문제 신고, 폰 연결 중계 세 가지이고, 광고·분석 업체로 가는 통신은 없다.
- "폰과 컴퓨터 사이 메시지는 종단 간 암호화된다"는 주장은 소스와 일치한다. 다만 메시지 종류·크기·시각은 중계 서버에 보이고, 상대 기기가 꺼져 있으면 암호문이 최대 7일 서버에 보관된다.
- 이용 통계는 설정이 켜져 있을 때만 전송된다. 다만 첫 설정 화면의 동의 칸은 처음부터 켜진 상태다.
- 두리가 여는 탭은 이용자의 로그인 상태를 그대로 쓴다. 두리가 그 탭에서 읽은 내용은 이용자가 고른 AI 서비스로 전송된다.
- 윈도우용 설치 파일에는 코드 서명이 없고, 맥용은 자체 인증서로 서명되어 있다. 배포 파일이 공개 소스로 만들어졌음을 외부에서 확인할 수단은 없다.

이 글은 확인된 사실과 확인하지 못한 사항을 구분해 적는다. 위법 여부에 대한 판단은 담지 않았다. 보안과 관련된 사항은 회사에 비공개로 알렸으며, 이 글에는 싣지 않았다.

## 2. 분석 대상과 방법

| 항목 | 내용 |
|---|---|
| 소스 | `github.com/kuzvo-dev/dool2`, 태그 `v0.4.3`, 커밋 `0f0f53946e3f20b8b6010127152dbf3c929da077` |
| 문서 | `dool2.com/privacy` (시행일 2026년 11월 23일), `dool2.com` 메인 페이지 (2026년 11월 24일 열람) |
| 운영자 | 쿠즈보(KUZVO) |
| 방법 | 공개 소스 읽기 |

앱을 설치하거나 실행하지 않았고, 회사 서버에 접속을 시도하지 않았다. 따라서 이 글의 내용은 "소스가 그렇게 작성되어 있다"는 뜻이다. 실제 배포된 설치 파일과 운영 중인 서버가 이 소스와 같은지는 확인 범위 밖이다.

## 3. 주장별 대조

### 3.1 "대화, 기록, 브라우저에서 읽은 페이지 내용은 내 컴퓨터에만 저장되고 저희 서버로 보내지 않아요"

소스와 일치한다.

- 소스에 있는 회사 주소는 `dool2.com/api/stats`(이용 통계), `dool2.com/api/report`(문제 신고), `relay.dool2.com`(폰 연결 중계)뿐이다.
- 대화와 설정은 PC의 SQLite 파일에, 작업 기록과 화면 캡처는 로그 폴더에 저장된다(`%APPDATA%\dool2` 또는 `~/Library/Application Support/dool2`).
- 이 파일들은 암호화되지 않은 상태로 저장된다. 로그는 7일, 화면 캡처는 3일 보관한다(`apps/daemon/src/journal.ts`). 로그인 금고와 암호화 키는 운영체제의 보안 저장 기능으로 따로 암호화된다.
- 업데이트 확인은 GitHub의 버전 파일을 받아 올 뿐이며 버전이나 기기 식별자를 보내지 않는다(`apps/desktop/src/update.ts`).

### 3.2 "두리 앱은 내가 고른 AI 서비스에 부탁과 필요한 페이지 내용을 보내요"

소스와 일치한다.

- AI(Claude Code, Codex 등)에는 두리가 제공하는 도구만 허용되고, 셸 명령 실행과 임의 파일 접근은 꺼져 있다(`packages/agent-claude/src/index.ts`, `packages/agent-codex/src/index.ts`).
- 두리의 도구는 바탕화면·문서·다운로드·사진·동영상 폴더의 파일을 읽고 옮길 수 있고(`apps/daemon/src/files.ts`), 이용자가 허용한 앱의 화면을 조작할 수 있다. 도구가 읽은 파일과 페이지 내용은 AI 서비스로 전송된다.

### 3.3 "두리 확장은 두리가 연 탭에서만 페이지를 읽고 누르고 입력해요. 내가 연 탭은 다루지 않아요"

탭의 경계는 소스와 일치한다.

- 확장은 두리가 연 탭의 목록을 따로 관리하고, 읽기·클릭·입력·화면 캡처 명령마다 대상 탭이 그 목록에 있는지 확인한다(`apps/extension/src/background.ts`의 `ownedTab`).
- 확장이 선언한 권한은 모든 http/https 사이트 접근과 디버거 권한이다(`apps/extension/static/manifest.json`). 범위 제한은 권한이 아니라 코드로 이루어진다.
- 두리가 연 탭은 이용자의 브라우저 프로필에서 열리므로, 이용자가 로그인해 둔 사이트는 로그인된 상태로 열린다. 이 점은 처리방침의 다른 문장("평소 로그인해 둔 그대로 써요")과 맞지만, "내가 연 탭은 다루지 않는다"는 문장만으로는 드러나지 않는다.
- 확장과 PC 앱 사이의 통신은 실행할 때마다 새로 만드는 토큰으로 인증한다. PC 앱의 로컬 서버는 `127.0.0.1`에만 열리고 모든 요청에 토큰을 요구한다(`packages/browser/src/bridge.ts`, `apps/daemon/src/index.ts`).

### 3.4 "사이트 로그인 정보는 두리 금고에만 있고, 그 사이트의 로그인 칸에만 채워요. AI 서비스에도 보내지 않아요"

소스와 일치한다.

- 금고는 Electron의 `safeStorage`(운영체제 키체인 또는 DPAPI)로 암호화해 저장한다(`apps/desktop/src/secrets.ts`).
- 채우기 전에 페이지의 출처가 저장된 사이트와 같은지 확인하고, 비밀번호는 비밀번호 입력 칸에만 채운다. AI에게는 채웠다는 사실과 글자 수만 전달된다(`apps/extension/src/background.ts`).
- 이용자가 PC나 폰에서 저장된 비밀번호를 볼 수 있는 기능이 있다. 폰에서 볼 때는 암호화된 폰 연결을 통해 전달된다.

### 3.5 "폰과 컴퓨터 사이의 메시지는 종단간 암호화돼서, 중계 서버도 내용을 볼 수 없어요"

소스와 일치한다. 다만 다음 사항은 문구에 드러나지 않는다.

- 키는 각 기기에서 생성되고, 연결은 PC 화면의 QR 코드와 6자리 확인 코드로 이루어진다. 메시지 본문은 X25519 키 교환과 AES-256-GCM으로 암호화된다(`packages/protocol/src/e2e.ts`).
- 봉투의 머리 부분(보낸 기기, 받는 기기, 메시지 종류, 순번)은 암호화되지 않는다. 중계 서버는 메시지의 종류, 크기, 시각을 알 수 있다.
- 받는 기기가 연결되어 있지 않으면 중계 서버가 암호화된 메시지를 보관한다. 최대 7일, 받는 기기당 500건이며 전달되면 삭제한다(`apps/relay/src/core.ts`). 사이트의 "내 대화는 저희한테 남지 않아요"라는 문구는 이 암호문 보관을 언급하지 않는다.
- 기기 쌍마다 고정된 키를 계속 사용한다. 설계 문서가 이를 명시하고 있다(`docs/decisions/0012-phone-link.md`).
- 푸시 알림은 PC가 푸시 서비스로 직접 암호화해 보내며, 회사 서버를 거치지 않는다(`apps/daemon/src/webpush.ts`).
- 중계 서버 소스가 저장소에 포함되어 있고, 설정에서 다른 중계 서버를 지정할 수 있다.

### 3.6 "사용 통계: 처음 설정이나 앱 설정에서 켠 경우에만, 하루 단위 숫자를 보내요"

전송 조건과 항목은 소스와 일치한다. 동의 화면의 기본 상태는 문구와 다르게 읽힐 수 있다.

- 설정값이 켜짐일 때만 전송하고, 값이 없거나 꺼짐이면 전송하지 않는다(`apps/daemon/src/stats.ts`, `apps/daemon/src/index.ts`).
- 전송 항목은 무작위 기기 번호, 날짜, 앱 버전, 운영체제, 그날의 횟수 집계, 연결된 AI의 종류, 확장 연결 여부, 연결한 서비스 개수다. 처리방침은 AI에 대해 "연결 여부"라고 적는데, 실제로는 어떤 AI인지가 전송된다.
- 첫 설정 화면에서 통계 동의 칸은 처음부터 켜진 상태로 표시된다(`apps/desktop/src/renderer/setup.ts`의 `shareStats = current.usageStats ?? true`). 이용자가 끄지 않고 확인을 누르면 켜짐으로 저장된다. "나중에"를 누르면 저장되지 않는다.

### 3.7 "문제 알리기: 대화 내용·파일 이름·사이트 주소는 빼고, 보내기 전에 확인할 수 있어요"

대체로 소스와 일치한다.

- 이용자가 설정에서 보낼 때만 전송되고, 미리보기와 실제 전송이 같은 함수로 만들어진다(`apps/daemon/src/report.ts`).
- 기록은 허용된 항목만 남기는 방식으로 걸러진다. 경로, 본문, 상세 설명 항목은 제외된다.
- 연결한 서비스의 식별자는 기록에 포함된다. 오류 문구는 홈 폴더 경로, 이메일 주소, 6자리 이상 숫자만 가린 뒤 포함되므로, 그 밖의 경로나 주소가 오류 문구에 들어 있으면 함께 전송될 수 있다.

### 3.8 "결제와 보내기는 승인이 필요해요"

승인 절차는 AI가 아니라 PC 앱의 코드가 강제하며, 승인에는 AI가 갖지 못하는 토큰이나 폰의 서명이 필요하다.

- 자동 승인 설정을 켜면 결제를 제외한 동작(보내기, 삭제, 인쇄, 파일 이동 등)이 승인 화면 없이 실행된다. 이 설정의 기본값은 꺼짐이다(`docs/decisions/0030-auto-approve.md`, `apps/daemon/src/auto-approve.ts`).
- 승인 절차와 관련한 그 밖의 사항은 회사에 비공개로 알렸으며, 조치 후 이 문서에 추가한다.

## 4. 배포 파일

- 설치 파일은 GitHub Actions에서 빌드된다. 빌드 과정에서 주입되는 값은 서명용 인증서와 업데이트 서명 키뿐이고, 서버 주소나 분석 키를 넣는 단계는 없다(`.github/workflows/release.yml`).
- 윈도우용 설치 파일에는 코드 서명 단계가 없다. 맥용은 Apple 개발자 인증서가 아닌 자체 인증서로 서명되며 공증 단계가 없다.
- 빌드 증명(attestation)이나 별도의 체크섬 파일은 없다. 해시는 서명된 업데이트 목록 파일 안에만 있다.
- 앱 내 업데이트는 목록 파일의 서명과 내려받은 파일의 해시를 확인한 뒤, 이용자가 설치를 누를 때 진행된다.

## 5. 확인하지 못한 사항

- 배포된 설치 파일이 공개 소스와 같은 내용인지
- 운영 중인 중계 서버가 공개 소스와 같은지, 서버 로그에 무엇이 남는지
- `dool2.com/api/stats`와 `dool2.com/api/report`가 받은 정보를 처리방침대로 보관·삭제하는지
- 실행 중인 앱의 실제 통신(앱을 실행하지 않았음)

## 6. 이용자가 참고할 점

- 첫 설정의 마지막 화면에서 이용 통계 칸의 상태를 확인한다. 설정에서 언제든 끌 수 있다.
- 두리가 여는 탭은 내 로그인 상태를 쓴다. 평소 쓰는 프로필과 분리하려면 별도의 크롬 프로필에 확장을 설치하는 방법이 있다.
- 자동 승인을 켜면 결제 외의 동작은 확인 없이 실행된다.
- 대화와 작업 기록은 PC에 암호화되지 않은 파일로 남는다. PC를 다른 사람과 함께 쓰는 경우 고려할 사항이다.
- 설치 파일에 서명이 없으므로 윈도우에서 설치할 때 경고가 표시될 수 있다.
